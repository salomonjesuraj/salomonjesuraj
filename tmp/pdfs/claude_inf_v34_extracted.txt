Objective: eliminate chart-timeframe dependency in the CE/PE anchor levels so the same symbol shows the same structural
CE/PE map on 5M and 15M charts, while keeping timeframe-specific confirmation (trend, volume, MTF, retest) exactly as it
works today.
1. Executive Summary
The review PDF correctly diagnoses the root cause: v3.3 builds its CE/PE trigger lines from a mix of
chart-timeframe-dependent series (stablePivotHigh, stablePivotLow, swingHigh, swingLow, boxHigh,
boxLow) and fixed-timeframe series (pdHigh/Low, prevWeekHigh/Low, hourSwingHigh/Low,
fourHourSwingHigh/Low). Worse, the selection logic (selectedCeRaw = nz(rawCeLocal, rawCeHtf))
prefers the unstable local set first, so the least stable levels win whenever they exist — which is most of the time.
This plan converts that into a two-layer engine, exactly as recommended in the review: a Level Engine that only reads
fixed anchor timeframes (15M/1H/4H/D/W) and therefore produces an identical CE/PE map regardless of chart
timeframe, and a Confirmation Engine that keeps reading the active chart timeframe for trend, volume, retest and
candle-pattern gates. Risk and Display layers are updated to match. A backward-compatible Micro Mode preserves the
current v3.3 chart-timeframe behavior as an opt-in for scalpers.
Estimated effort: 4–6 focused engineering hours plus 1–2 hours of on-chart regression testing across symbols and
timeframes.

PHASE 1  —  Add Fixed-Anchor Variables
Risk: Low
Add alongside the existing pdHigh/prevWeekHigh block (same request.security pattern already used in v3.3, so no
new technique is introduced):
groupAnchor = "Level Anchor"
levelAnchorMode = input.string("Fixed MTF Anchors", "Level anchor mode",
options=["Fixed MTF Anchors", "Micro Mode (chart TF)"], group=groupAnchor)
anchorTF = input.timeframe("15", "Anchor timeframe (intraday structure)", group=groupAnchor)
anchorLookback = input.int(24, "Anchor lookback bars", minval=10, maxval=100, group=groupAnchor)
showAnchorRow = input.bool(true, "Show Anchor TF / Confirmation TF panel rows",
group=groupAnchor)
// Fixed-timeframe structure -- identical output regardless of chart timeframe
anchor15High = request.security(syminfo.tickerid, anchorTF, ta.highest(high, anchorLookback)[1],
barmerge.gaps_off, barmerge.lookahead_off)
anchor15Low = request.security(syminfo.tickerid, anchorTF, ta.lowest(low, anchorLookback)[1],
barmerge.gaps_off, barmerge.lookahead_off)
anchor15BoxHigh = request.security(syminfo.tickerid, anchorTF,
ta.highest(high, math.max(6, math.floor(anchorLookback / 2)))[1], barmerge.gaps_off,
barmerge.lookahead_off)
anchor15BoxLow = request.security(syminfo.tickerid, anchorTF,
ta.lowest(low, math.max(6, math.floor(anchorLookback / 2)))[1], barmerge.gaps_off,
barmerge.lookahead_off)
Note the trailing [1] inside every expression, matching the pattern v3.3 already uses for hourSwingHigh/fourHourSwingHigh. This forces
each anchor to read the last closed bar on the anchor timeframe, so values cannot repaint intrabar — the same non-repainting guarantee the
fixed 1H/4H/D/W levels already have.
PHASE 2  —  Refactor Nearest-Level Helpers to N-ary
Risk: Medium
The current f_nearestAbove/Below and f_meaningfulAbove/Below take exactly 4 fixed parameters. Once
pivot/box/swing are removed from the fixed set and anchor15High/Low are added, the candidate list needs to hold 6+
levels. Replace with array-based versions:

f_nearestAbove(float price, array<float> levels) =>
    float best = na
    for lvl in levels
        if not na(lvl) and lvl > price and (na(best) or lvl < best)
            best := lvl
    best
f_nearestBelow(float price, array<float> levels) =>
    float best = na
    for lvl in levels
        if not na(lvl) and lvl < price and (na(best) or lvl > best)
            best := lvl
    best
f_meaningfulAbove(float price, float minDistance, array<float> levels) =>
    f_nearestAbove(price + minDistance, levels)
f_meaningfulBelow(float price, float minDistance, array<float> levels) =>
    f_nearestBelow(price - minDistance, levels)
This is a drop-in behavioral equivalent for the existing 4-argument call sites elsewhere in the script (e.g. ceHistT1/ceHistT2 target logic) —
just pass array.from(a, b, c, d) there to avoid touching Section 7 (targets) in this pass.
PHASE 3  —  Rewire CE/PE Candidate Selection
Risk: Medium
Replace the local/HTF split with a single mode-aware candidate list, fixed anchors first:
fixedCeLevels = array.from(anchor15High, orbHigh, pdHigh, prevWeekHigh, hourSwingHigh,
fourHourSwingHigh)
fixedPeLevels = array.from(anchor15Low, orbLow, pdLow, prevWeekLow, hourSwingLow,
fourHourSwingLow)
microCeLevels = array.from(stablePivotHigh, swingHigh, boxHigh, anchor15High)
microPeLevels = array.from(stablePivotLow, swingLow, boxLow, anchor15Low)
useMicro = levelAnchorMode == "Micro Mode (chart TF)"
ceLevels = useMicro ? microCeLevels : fixedCeLevels
peLevels = useMicro ? microPeLevels : fixedPeLevels
minLevelDistance = atr * minLevelDistanceAtr
selectedCeRaw = f_meaningfulAbove(close, minLevelDistance, ceLevels)
selectedPeRaw = f_meaningfulBelow(close, minLevelDistance, peLevels)
fallbackCe = useMicro ? nz(stablePivotHigh, nz(swingHigh, high)) : nz(anchor15High,
nz(hourSwingHigh, high))
fallbackPe = useMicro ? nz(stablePivotLow, nz(swingLow, low)) : nz(anchor15Low, nz(hourSwingLow,
low))
candidateCe = nz(selectedCeRaw, fallbackCe) + atr * bufferAtr
candidatePe = nz(selectedPeRaw, fallbackPe) - atr * bufferAtr
Everything below this point in v3.3 — working-level lock, freeze-on-breakout, ceAbove/peBelow resolution — is
untouched. It already operates purely on candidateCe/candidatePe, so it inherits the stability fix automatically.

6. Optional Hardening (Phase 6 & 7 — not required for the core fix)
PHASE 6  —  Fixed-Timeframe ORB Reconstruction
Risk: Medium
The review rates ORB stability as “Partly” — it uses real clock time (dayStartTime + orbMins * 60000) so drift is
at most one chart-bar width, which is usually immaterial. If exact parity is required, rebuild the ORB accumulator on a
fixed 1-minute series via request.security(syminfo.tickerid, "1", ...) with the same accumulation
pattern, then discard the chart-bar version. Treat as a nice-to-have, not a blocker.
PHASE 7  —  Stable Pivot on Anchor Timeframe (advanced)
Risk: High
Only pursue this if 15M range highs/lows (Phase 1) prove too wide in testing. It requires moving the stateful var
stablePivotHigh accumulation into a user-defined function and evaluating it inside request.security so the
persistent variable runs in the anchor timeframe's context, not the chart's. This is a well-known but fragile Pine v6
pattern (context-switched stateful UDFs) and needs isolated testing before merging — budget extra time and treat it as
a separate release, not part of the v3.4 core fix.

9. Summary
The fix is contained: five code phases (1–5) touch level selection and display only, none of them alter the Confirmation
Engine, Risk Engine formulas, alert conditions, or visual styling that already work. Phases 6–7 are optional hardening,
not required to close the review's core finding. Once Phase 8 passes on at least two symbols across 5M/15M, the same
stock will tell the same structural CE/PE story on both charts, exactly as the review's Section 9 final recommendation
specifies.
