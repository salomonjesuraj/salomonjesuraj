0. CONTEXT READ THIS FIRST
The safety layer, execution staging, and journal architecture of
v5.0.0 are sound. Do not rebuild them.
The problem is different and more serious: the numbers the system
currently produces are not trustworthy, for four reasons.
1. Option P&L is computed without transaction costs or spread
crossing.
2. Option stop-loss is derived from a hardcoded constant (28%)
instead of from the underlying stop and delta.
3. Nothing checks whether the underlying target actually clears
the option's breakeven.
4. Paper trades are logged manually and therefore selectively.
Until these four are fixed, every analytic, every precision number,
and every optimizer output in the system is noise. No new features,

CR-1 Central cost & slippage model
Create a single cost_model module. Journal, Execution Staging,
and Analytics must all call it. No component computes P&L
independently.
Fill assumptions (non-negotiable):
Entry fill = ask price
Exit fill = bid price
Never LTP. Never mid. Never last traded premium.
Per-trade cost components to model:
Brokerage (flat per executed order, both legs)
STT on the sell side of options premium
Exchange transaction charges
SEBI turnover fees
GST on (brokerage + transaction charges)
Stamp duty on the buy side
Output contract:

CR-2 Remove the hardcoded 28% premium stop-loss
Delete the constant entirely. Derive the option stop from the
underlying stop and delta.
underlying_risk = abs(entry_underlying -
sl_underlying)
premium_risk = underlying_risk * abs(delta)
option_sl_price = entry_premium - premium_risk
premium_risk_pct = premium_risk / entry_premium
Guard rails:
If premium_risk_pct < 0.12 → BLOCK ticket. Reason:
"SL inside spread — noise stop" .
If premium_risk_pct > 0.45 → BLOCK ticket. Reason:
"strike too far OTM for this SL distance" .

CR-6 Auto-log every signal

ONE-LINE BRIEF
The safety and execution layers are fine. The problem is that we
compute option P&L without costs, derive stops from a
hardcoded constant, never check whether the target clears
—
breakeven, and log trades selectively so none of our current
numbers mean anything. Fix those four first, then freeze
features for three months of clean data.
Note: this document covers system design and data integrity only. It
is not investment advice, and shipping these changes does not
—
establish that the strategy has an edge it establishes that the
system can finally measure whether it does.
